# Four-minute demonstration script

Record this only after live-model evaluation meets the acceptance threshold. For a simulator walkthrough, keep the mode banner visible and label the video as development evidence, not the final AI demonstration.

| Time | On screen | Narration |
| --- | --- | --- |
| 0:00–0:25 | Requests workspace | “A donated walking aid helps nobody while it waits in the wrong depot. NeighborGear helps community coordinators carry a request all the way to a confirmed delivery.” |
| 0:25–0:55 | New request; missing details | “A request arrives. The agent identifies what is missing and asks a focused question. Here, the required equipment specifications are provided by staff.” |
| 0:55–1:35 | Candidate comparison and approval | “NeighborGear searches the network, explains why some items are excluded, and presents an available match. The coordinator confirms suitability; the application reserves the item.” |
| 1:35–2:20 | Transport assignment; inject cancellation | “Then the driver cancels. The agent finds an alternative that satisfies the delivery window and capacity, and updates the correspondence.” |
| 2:20–2:55 | Confirm delivery, advance clock, return | “The loan is tracked, a reminder is created, and the return moves the item into inspection. It cannot be offered again until staff record a pass.” |
| 2:55–3:30 | Architecture and activity record | “Strands connects the language model to tools that act on persistent records. Application rules prevent duplicate reservations and protect the review boundary. This activity record shows what actually happened.” |
| 3:30–4:00 | Results and closing workspace | State only verified evaluation results. “This is a fictional network and a working prototype. The next step is validating the workflow with an equipment-reuse charity.” |

Keep model waiting time visible or identify edits/time compression. Do not narrate simulated recipients as real partners or imply an inspected item was physically inspected by the software.
